# Upgrading

## From 0.3 to 0.4

The [changelog](CHANGELOG.md) lists everything; this is what you may have to do. Run `cordon:verify` once after updating and go through the steps it points to.

1. **Fix any configuration error.** `config/cordon.php` is now validated before anything is analysed ([ADR 0019](docs/adr/0019-strict-configuration.md)): unknown keys (`depend_on`), unknown modules, dependencies on modules that do not exist and unknown rule ids exit with code `2` and name the closest valid key. These were silently ignored before, so fixing them may change what is checked. `null` is no longer accepted where a list or a setting is expected: `'modules' => null`, a module set to `null` (`'Shared' => null`) and a rule set to `null` or `1` are errors; remove the entry, or use `[]`, `true`/`false` or `error`/`warn`/`off`. Two custom rules with the same id also exit with code `2`. `toRespectBoundaries()` fails on the same errors, so a Pest suite that passed with a typo in the config now fails.
2. **Check your cycles.** A listener of another module's event no longer closes a cycle ([ADR 0016](docs/adr/0016-listener-edges.md)). If your baseline recorded such cycles, `cordon:verify` now says those entries no longer match: remove them with `cordon:verify --prune-baseline`. To keep the 0.3 behaviour, set:

   ```php
   'listeners' => ['cycles' => true],
   ```
3. **Expect warnings from the code outside the modules.** `app`, `routes` and `database` are now checked by the `host_access` rule, even if your published config has no `host` key ([ADR 0017](docs/adr/0017-host-module.md)). It starts as a warning, so it never fails: set `'host_access' => 'error'` to enforce it, or `'host' => ['paths' => []]` to leave that code unchecked. The file counts (`summary.files` in JSON, the text report) now include those files. A module named `host` is an error while `host.paths` is set: rename it, or set `host.paths` to `[]`. Two more rules start as warnings, `unused_dependency` and `public_api_leak`; `layers` checks nothing until you configure `layers`.
4. **Optional: switch rules to severities.** `true` and `false` keep working ([ADR 0015](docs/adr/0015-rule-severities.md)). To adopt a rule gradually, set it to `'warn'`: its violations are reported but do not fail, and the baseline neither records nor hides them. `--fail-on-stale` is also new: it fails when a baseline entry no longer matches the code.
5. **If you parse the JSON report**, it now starts with `"version": 1`, adds `summary.warnings`, `summary.ignored`, a `warnings` list, and a `severity` and a `docs_url` on every violation ([ADR 0018](docs/adr/0018-json-report-version.md)). Nothing was removed or renamed. The schema is `resources/schemas/report-v1.schema.json` in the package, and it accepts fields it does not list.
6. **If you use the PHPStan extension**, PHPStan now also reports `cordon.undeclaredDependency` and `cordon.cycle`, which can fail a run that passed, and `cordon.incompleteGraph` when its `paths` leave a module out. Add the module directories to `paths`, or ignore `cordon.incompleteGraph` if you analyse parts of the project on purpose. The rules report only while their rule is `error`.
7. **If you wrote custom rules**, the classes they use are marked `@api` and are covered by the [compatibility](https://chrisabner.github.io/Cordon-Modulith/guide/compatibility) page. Classes marked `@internal` (such as `Analyzer` or `RuleSet`) may change in any release. A violation of a rule set to `error` is reported as an error whatever severity your rule gave it. If you called `ModuleMap::configurationWarnings()`, use `Cordon\Support\ConfigValidator::errors()`.
8. `nikic/php-parser` 5.3 or later is required. Composer upgrades it when you update Cordon.
9. **If some modules live outside the project root** (a monorepo with `../packages`), their files are now written with `../` in reports and in the baseline, instead of an absolute path. Regenerate the baseline once with `cordon:verify --generate-baseline`.
10. **If you tried `layers` from a development version before 0.4.0**, its baseline entries are now per class (ADR 0014): the target is the class that crosses the layer, not the module. Regenerate the baseline once with `cordon:verify --generate-baseline`. Releases before 0.4 had no `layers`, so nothing else changes.
